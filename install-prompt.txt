Install DeltaBox Lite on this machine and verify that it works. Carry out the
installation, rather than only describing the steps. Use the user's requested
project directory when one is provided.

Project: https://github.com/delta-box/deltabox-lite
Documentation: https://github.com/delta-box/deltabox-lite/blob/main/README.md
DSH integration: https://github.com/delta-box/dsh-deltabox
Pi integration: https://github.com/delta-box/pi-deltabox

1. Inspect the environment.

Detect the operating system, CPU architecture, shell, installed deltabox,
Node.js/npm, and any DSH or Pi installation. Supported prebuilt targets are
macOS and Linux on arm64 and x64. Linux prebuilts require glibc 2.39 or newer.
For CB-CoW, check /dev/fuse and fusermount3 or fusermount on Linux, or an APFS
project volume on macOS. If the platform is unsupported, report that clearly.
Read the current project and integration documentation before choosing a
fallback. Preserve existing configuration and unrelated project changes.

2. Install the CLI.

Reuse a working installation when suitable. Otherwise choose one available
method; do not run every installer:

  brew install delta-box/tap/deltabox

  npm install --global deltabox-lite

Or download and inspect the official installer, then execute it with sh:

  https://raw.githubusercontent.com/delta-box/deltabox-lite/main/scripts/install.sh

The installer verifies release checksums and defaults to ~/.local/bin without
sudo. Add that directory to the current PATH if needed; make any persistent
shell PATH edit idempotent. DELTABOX_VERSION and DELTABOX_INSTALL_DIR can select
a version and destination. Do not bypass checksum failures. If no compatible
prebuilt exists, use the documented source build with Rust 1.87 or newer:

  cargo build --release

Build in a separate checkout and expose target/release/deltabox on PATH. Report
missing build prerequisites rather than claiming that installation succeeded.
Run deltabox --version and deltabox --help after installation.

3. Install the agent integration the user uses.

If the user named DSH or Pi, install that integration. Otherwise infer it from
the available tools and project context. If the choice is ambiguous, ask which
integration they want while continuing the standalone CLI verification. Do not
install an unrelated agent application by default.

For DSH (DeepSeek Harness), use the selected profile:

  dsh plugin --profile web add dsh-deltabox

For Desktop, use Desktop's bundled CLI:

  dsh plugin --profile desktop add dsh-deltabox

Desktop also supports Plugins > Add plugin > dsh-deltabox. The published plugin
installs its matching runtime and native platform dependency. Installing it
with npm globally does not activate it in Harness. Check current package peer
requirements against the installed Harness version; the plugin currently
supports 0.2.0-rc.2 and 0.2.1-alpha.2 and requires Node.js ^22.19.0 or >=24.0.0.
Reload or restart the chosen profile after installation. If Harness is absent,
consult its official installation instructions linked by the plugin docs.
Keep existing model credentials; never print API keys or invent credentials.

For Pi, install the host if requested and missing:

  npm install --global @earendil-works/pi-coding-agent

Then install the extension:

  pi install npm:pi-deltabox

Check the current Pi Node.js requirement before installation (currently
>=22.19.0). The extension includes its native runtime; installed prebuilds do
not need explicit bin or nativeAddon paths. Start a new Pi session and verify
with /sandbox-status. Use /sandbox-review, /sandbox-commit, and /sandbox-abort
for review decisions. Merge any necessary deltabox.json settings into existing
configuration rather than replacing it. Consult the extension guide to select
command isolation explicitly: its default isolation setting is none. Native
mode never silently substitutes another filesystem mode; explicitly configure
copy-private when CB-CoW is unavailable and explain the change.

4. Verify in a disposable directory, never in the user's working files.

Run this smoke test with the installed CLI in a subshell:

  (
    set -eu
    demo=$(mktemp -d)
    cd "$demo"
    printf 'original\n' > notes.txt
    deltabox run --abort -- sh -c 'printf "sandboxed\n" >> notes.txt; printf "generated\n" > generated.txt'
    test "$(cat notes.txt)" = original
    test ! -e generated.txt
    deltabox run --commit -- sh -c 'printf "accepted\n" > accepted.txt'
    test "$(cat accepted.txt)" = accepted
    printf 'Smoke test passed in %s\n' "$demo"
  )

This checks both rollback and acceptance. Inspect any failures and report the
resolved filesystem mode or fallback shown by the runtime. Do not hide a
failure by disabling confinement. Also verify the selected integration loads
its native runtime and exposes its review controls. If interactive access or
model credentials are unavailable, state which checks remain for the user.

configuration changes, smoke-test results, and any remaining steps. Explain
